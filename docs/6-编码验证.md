# 编码验证

如何验证我们的 LDAC 和 SBC 流是正确的。全部过程可在开发者机器上复现，无需耳机和驱动。

## 工具

- `build\ldacenc.exe` —— WAV → LDAC（`--raw` 输出「裸」帧）。
- `build\ldacsvc.exe --sink null --dump файл` —— 通过服务完成同样的事：float 输入、重采样、封装、剥离头部。
- `tools\ldacverify\build-ldacdec.cmd` —— 用开源解码器 libldacdec（提交 `c90094b1`，替换了 GNU 宏 `min`/`max`，代码本身未改动）构建 `build\ldacdec_wav.exe`。解码器不纳入 git。
- `ffmpeg -f sbc -i файл out.wav` —— 系统自带的 SBC 解码器。
- `tools\hci\snr.py эталон.wav декодированный.wav` —— 搜索延迟，用最小二乘法拟合增益，打印延迟、增益和 SNR。

## 结果（2026-10-22）

| 流 | 信号 | 延迟 | 增益 | SNR |
|---|---|---|---|---|
| SBC 48 kHz，joint stereo，bitpool 53（服务） | 1 kHz 正弦，−6 dB | 25 | −0.01 dB | 63.3 dB |
| LDAC HQ 96 kHz（`ldacenc`） | 1 kHz 正弦 | 256 | +6.02 dB | 58.6 dB |
| LDAC SQ 96 kHz（`ldacenc`） | 1 kHz 正弦 | 256 | +6.02 dB | 58.6 dB |
| LDAC MQ 96 kHz（`ldacenc`） | 1 kHz 正弦 | 160 | +6.02 dB | 58.6 dB |
| LDAC SQ 96 kHz（服务，float 输入） | 1 kHz 正弦 | 256 | +6.02 dB | 58.6 dB |
| LDAC HQ / SQ / MQ | 粉红噪声 | 256 | ≈ +5.9 dB | 16.6 / 11.5 / 9.2 dB |

结论：

- LDAC 和 SBC 帧都能由独立解码器正确解码，两个声道都在，采样顺序正确。
- +6.02 dB（正好 ×2）的电平偏移在任何质量、任何输入下都相同（`ldacenc` 中为 S16，服务中为 float）。它来自 libldacdec 的 32 位输出：同一脚本下的对照 SBC 显示 0 dB。这是解码器的特性，而非我们编码的问题。
- 正弦信号上的 SNR 在三种质量下都相同（58.6 dB）：纯音的编码有充足余量，上限由解码器决定。在宽带噪声上，各质量的排序正确：HQ > SQ > MQ。噪声上绝对值偏低对感知编码器而言是正常的。
